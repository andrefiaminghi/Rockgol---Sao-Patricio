# Sincronismo Supabase e PWAs Independentes (Juiz e Torcida) — Plano de Implementação

> **Para workers agênticos:** SUB-SKILL OBRIGATÓRIA: use `afr-superpowers:executing-plans` (recomendado para execução em etapas sequenciais com checkpoints) ou `afr-superpowers:subagent-driven-development` para implementar este plano task-por-task. Passos usam sintaxe de checkbox (`- [ ]`) para rastreamento.

**Objetivo:** Integrar persistência e sincronização de dados via Supabase com modelo offline-first, dividindo a aplicação em dois PWAs no mesmo deploy: Torcida (`index.html`) em modo leitura com simulação local e botão "Sincronizar", e Árbitro (`juiz.html`) protegido por PIN com permissões completas de edição e sincronização em tempo real.

**Arquitetura:** Vite Multi-page com dois entrypoints HTML (`index.html` e `juiz.html`), serviço de dados desacoplado `@supabase/supabase-js` em `src/services/supabaseService.ts`, persistência prioritária em `localStorage` para tolerância a falhas de rede, e Service Worker unificado em `public/sw.js` com estratégia Network-First para documentos e Cache-First para assets.

**Stack técnica:** React 19, TypeScript 5.7, Vite 6.2, Tailwind CSS 4, `@supabase/supabase-js`, Vitest 3.
